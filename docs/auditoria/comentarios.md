# Auditoría — feature «comentarios»

**Alcance.** `POST /posts/:slug/comentarios`, `PATCH /comentarios/:id`, `DELETE /comentarios/:id`,
el listado de comentarios dentro de `GET /posts/:slug` y el recuento `num_comentarios` de
`GET /posts` y `GET /posts/:slug/relacionados`. Backend en `backend/start/routes.ts`, tabla
`comentarios`, semilla, test `comentarios.spec.ts`, y en la web `Comentarios.jsx`,
`DetallePost.jsx`, `ListaPosts.jsx` y `PostsRelacionados.jsx`.

**Contraste.** Las reglas de negocio del README (R1–R6) y las reglas de arquitectura de `CLAUDE.md`.

**Qué es y qué no es esta auditoría.** Es una lista curada de hallazgos señalados y comprobados. No
propone soluciones ni ordena los hallazgos: el diseño de las correcciones y su prioridad los decide el
equipo que recibe la auditoría. El id (**H1**…**H18**) es solo una referencia para citarlos entre sí,
no un orden.

**Cómo se ha comprobado cada hallazgo.** La casilla «Dónde está» indica si se comprobó **en vivo**
(peticiones `GET` contra la API levantada con la semilla) o **leyendo el código**. No se lanzaron
`POST`, `PATCH` ni `DELETE` para no modificar la base de datos.

**Cómo se cuentan los sitios.** Se cuentan los sitios donde **está el defecto**: cada línea o bloque
que tiene el fallo, sea cual sea la corrección que elija el equipo. No se cuenta el código que solo
está relacionado.

**Decisión de producto recibida.** `'Aprobado'` y `'ok'` en `comentarios.estado` cuentan como aprobados.
